# K25 技术设计

用户可见要求以 [PRD](prd.md) 为准。本文定义会话存储、文件记录与回退的边界。

## 模块职责

| 层 | 改动 |
| --- | --- |
| `chat.py` | 为现有会话格式增加可选的检查点会话标识和当前版本。复用会话序列化、脱敏与原子保存。支持同一会话在原路径更新，以及创建不覆盖同名会话的存档。 |
| `checkpoints.py`（新增） | 维护项目和会话隔离的清单、快照、回退计划、预算和恢复记录。使用标准库，按需导入。 |
| `tools/__init__.py`、`tools/workspace.py` | 在实际执行工具的位置记录可支持的文件变更，复用 `prepare_mutation` 已准备的备份。共享路径校验和单文件恢复原语。 |
| `cli.py`、`cmd_handler.py` | CLI 管理用户轮次和会话切换。命令处理器负责参数、预览、确认、输出和刷新界面。工具执行线程通过显式传递的轮次记录器写入当前轮的记录。 |
| `const.py` | 使用既有配置注册方式公开三个设置。通过现有命令表提供帮助和补全。 |

检查点由 CLI 管理。工具返回格式、提供商接口和模型上下文保持现有契约。使用固定的本地记录结构，首版无需引入 Git、数据库、后台进程或新依赖。

## 会话与存储

在实际会话存储目录下使用 `checkpoints/<project-key>/<session-id>/`。项目键复用 `project_sessions_key(resolved_cwd)`。即使 `CHAT_HISTORY_DIR` 指向共享目录，检查点仍按项目键隔离。会话标识使用随机 UUID，独立于标题、索引、时间戳和文件名。恢复前核对项目、工作区根、会话保存路径、会话标识和当前版本。通过 `/save` 改名时由会话管理器更新保存路径。复制的会话文件可照常读取对话，在新身份下建立检查点。

存储由一个带版本的索引和它引用的快照、备份组成。每个记录包含父编号、单调增长的编号、轮次、时间和该轮从父点到轮末的有序变更清单。计数器在回退后保留高水位，避免旧编号指向不同内容。变更条目包含工作区相对路径、两端内容摘要或不存在标记、文件模式以及受索引约束的备份引用。普通文件以流式 SHA-256 和文件类型、模式对比，空父目录只允许检查类型并在为空时移除。

复用 `Chat.to_dict()` / `Chat.from_dict()` 的消息格式和现有脱敏策略。快照保存当时实际保留的对话历史，包含工具消息和图片。快照中可保留当时的计划引用用于校验。计划、模型、角色、费用统计以及持久上下文继续由各自的模块管理。回退恢复对话历史，保留回退时在用的模型、角色和费用统计。历史恢复后刷新上下文占用，清掉后续轮次的 `/retry` 和工具输出视图缓存。回退会清除该会话当前进程中的旧 `/undo` 记录，避免指向已经撤销的文件版本。

文件与目录使用现有私有权限策略（POSIX 上 0600 和 0700），写入采用同目录临时文件和原子替换。文件备份的原始字节要用于恢复，不能应用文本脱敏。检查点仅引用可校验的自有副本或硬链接。源文件与备份文件本身不能共用 inode。平台不支持硬链接时才复制既有备份，纳入 K25 字节预算。清理只删除 K25 拥有的文件，现有 `.yaicli-backups` 与 `/undo` 的清理由原机制管理。

索引保留连续可用的一段记录。按条数和实际拥有的字节预算清除最旧记录，把最早保留记录改为无父点的基准。快照超限或文件记录不完整时切断此前回退链。在当前状态可以完整保存时再建立基准。忽略损坏、缺失或不明版本的索引并输出诊断，旧 JSON 会话无需迁移。关闭功能后会话照常保存，并在正常保存时清除与旧索引的当前版本关联。再次启用从新基准开始。

## 轮次如何完成记录

1. 已经保存或通过指定标题开启的持久化交互聊天，在首个可记录轮次前建立基准。已有历史的临时聊天成功执行 `/save` 时，以当时状态建基准。跳过临时、禁用、非 TTY、`--quiet` 和机器输出路径的 K25 IO。
2. CLI 在 `_process_user_input` 开始前创建记录器。成功通过权限和工作区守卫后，由工具分发层在实际操作前取得变更前状态，操作结束后记录结果与变更后状态。读取、审批拒绝和 dry-run 不写入变更。操作失败时比较涉及路径的前后状态，有副作用或无法判断就标记中断。外部工具实际被调用、`!` 或执行模式真正执行命令时视为未记录副作用。记录器绑定明确的会话和轮次，避免旧线程写入新轮次。
3. 接受现有历史裁剪和工具消息配对后的轮末状态。会话持久化、索引、变更记录用同一版本核对。文件工具实际开始前保留待完成标记，中途退出后读取旧记录能发现断点。未完成的 worker 仍可能持有文件操作，先阻止回退，等 worker 退出后才能从稳定状态建立新基准。
4. `/retry` 是新尝试，仍从重试前的实际文件状态记录变更。它沿用现有历史恢复逻辑，回退到重试前可恢复此前显示的历史。`/compact` 只改变当前历史，下一个检查点保存裁剪结果。`/clear` 清除当前会话的可回退记录。`/undo` 一旦尝试并可能改变文件，就在当前状态重建基准。持久计划修订、执行推进或计划相关状态变化形成恢复边界。计划独立存储且按会话绑定，首版由 `/plan` 管理。恢复同一计划状态内的普通聊天时，校验计划引用和修订未变，保留当前计划状态。
5. `/load` 与 `--resume` 只恢复匹配项目和版本的检查点。已有按项目隔离的会话列表保持会话入口。删除或因会话数量上限淘汰聊天时，清理其检查点存储，未完结的恢复记录单独保留并报告。一个会话只能由一个写入者推进。不同会话仍可在同一项目工作，回退通过有效工作区锁和路径校验拒绝冲突。

## 回退提交与故障恢复

1. 生成回退预览前，验证当前会话版本和目标点之间的全部记录。按从新到旧的顺序模拟反向应用，同一路径在多轮、同一轮重复出现都要检查变更链是否能接起来。只将当前文件与最新记录对比，较早变更通过模拟状态对比。移入、移出和重命名一起校验。合并预览中同一路径的最终操作。
2. 逐个验证涉及的目标和备份。复用工作区边界及保护路径规则，拒绝异常路径、符号链接及其他不支持的文件类型。禁止在工作区外改动，禁止改动内部会话、备份和计划存储。需要删除目录时仅删除由本次链条创建、最终为空的目录。范围由变更记录给出，不扫描整个工作区。
3. 用户确认后取得该工作区和当前会话的写锁，并重新执行预检。回退、受守卫的文件工具和 `/undo` 使用同一工作区写锁。对外部编辑，在应用每笔回退前再次校验。将涉及路径的当前内容与源会话版本写入受保护的恢复记录，确认空间够用再开始。对普通文件用就地原子替换，按依赖顺序移除新建文件和空目录。
4. `/fork` 在第一笔回退写入之前提交一个独立的已保存会话。存档仅复制对话和会话元数据，以新身份打开。会话绑定的计划、检查点链和文件内容由源会话持有。保留用户给出的标题大小写，缺省标题按时间生成并避免冲突。存档保存本身失败时直接停止。存档成功后若回退故障，保留存档并在结果里给出标题。
5. 先完成文件恢复，再以同一提交编号写入聊天和索引。恢复记录包含源版本、目标版本和相关路径两端的摘要。若某一步失败，按恢复记录补偿已应用的文件及会话改动。若补偿仍失败，保留恢复记录，列出需要处理的路径及私有恢复记录的位置。进程中断后读取恢复记录。文件和两份会话状态完全匹配目标版本时完成整理，完全匹配源版本时丢弃失败记录。混合状态保留恢复记录并提示用户手动恢复至任一完整版本，后续回退在匹配前停止。启动时的核验只读工作区。成功后才淘汰较新检查点和相关对象，并通过现有审计写入回退或分支的结果。审计只记录会话、检查点、结果和计数，沿用既有脱敏规则。

多个文件没有通用的跨文件原子替换。通过全量预检、逐路径校验与有界补偿来控制失败范围。回退不捕获工作区的全量状态，外部进程的副作用仍由对应系统管理。

## Feature examples

以下为诊断输出示例。用户在预览后按 `y`，但 `trip.md` 此时已被另一进程改过。

```text
💬 > /rewind 1
Rewind to checkpoint #1 and drop 1 turn?
  Restore: trip.md
  Remove:  packing.md
Proceed? [y/N]: y
Cannot rewind: trip.md changed outside the recorded history.
💬 >
```

列表与提示走 stdout，冲突提示走 stderr。确认后的预检失败时，聊天记录、待删除文件及所有检查点保持原状。REPL 继续运行。无需为这个操作增加进程退出码，非交互模式沿用现有输出契约。对应 PRD A3。
