# 第三阶段：明确会话状态与配置传递

## Goal

完成父任务 R3：明确应用会话中计划状态与有效配置的所有权，减少 CLI、模型客户端和工具层的隐式状态同步，并用实例隔离测试验证实际数据流。

## Background

依赖第一、第二阶段合并到 master。原始证据：config.py:365—375；cli.py:873—919；llms/client.py:130—194；tools/__init__.py:70—101、169—198；tools/function.py:252—312；plan_mode.py:526—549；tests/conftest.py:131。

配置加载优先级和独立工具兼容边界仍有效；本任务仅调整运行时取得及持有依赖的方式，不改用户的配置来源或文件格式。

## Requirements

- S3-R1：每个实际应用会话持有一份有效配置及一个 PlanSession；从组装到计划协调、模型调用、工具声明及执行均使用所属依赖。
- S3-R2：工具可见性由所属计划状态和配置派生，不再要求 CLI 向全局工具模式同步副本；缓存不得把一个会话的模式或选择条件用于另一个会话。
- S3-R3：配置按现有优先级解析一次，运行时变更作用于所属会话的后续请求。隔离嵌套配置值，/model、/role、恢复会话及客户端重建保持现有用户语义。
- S3-R4：独立 builtin/user 工具仍通过兼容执行边界接收配置，保持原 execute 签名。配置 root 在首个文件工具之前生效，其他会话和失败调用的托管环境状态不能影响本次执行。
- S3-R5：旧公开入口仍可在未显式提供依赖时使用懒建默认适配；产品主路径不得依赖该回退。保留启动性能和数据格式。

## Feature examples

沿用父 PRD E1—E3。内部隔离示例不增加用户命令：

~~~text
会话 A：readonly，普通模式
会话 B：standard，计划模式
A 的工具声明及执行规则保持 A 的配置
B 的工具声明包含其当前计划模式允许的工具
切换 B 的计划状态后，A 的模式、配置和声明保持不变
~~~

该示例由测试构造应用实例，假 provider/MCP，不向终端新增提示。验证文件变更时，两实例均使用 standard/普通模式，分别将 WORKSPACE_ROOT 指向临时目录 A、B，交替执行工具只修改各自允许的路径；异常后下一次调用仍使用所属配置。readonly/计划模式的拒绝另行验证。既有拒绝消息、stdout/stderr 和退出码不变。

## Out of scope

不增加同进程多应用并行调用能力，不支持并发改变 cwd；不全面移除 cfg/console/函数加载缓存等所有单例，不将撤销栈及输出查看器全面改造成跨实例持久服务。不新增配置、用户 API、数据迁移或并发框架。

## Acceptance criteria

- S3-A1 对应 S3-R1/R2：用两个真实运行时实例交替改变计划模式、生成三种 provider 声明并执行会话工具，互不污染；无需 reset_plan_session/set_plan_tool_mode 全局重置才通过。
- S3-A2 对应 S3-R3：不同工具筛选、权限、输出限制及嵌套配置相互隔离；同会话内模型/角色切换、客户端重建和保存/恢复仍通过既有行为测试。
- S3-A3 对应 S3-R4：不同 workspace root 的真实临时文件调用、异常、拒绝及后续调用结果正确，独立用户工具的 schema/签名/覆盖行为不变；托管环境清理不破坏 undo/rewind。
- S3-A4 对应 S3-R4/R5：配置文件单独指定 root 且 cwd 为子目录、没有继承 YAI_WORKSPACE_ROOT 的跨进程检查点用例，sync/stream 均通过。
- S3-A5 对应 S3-R5：默认兼容入口和显式实例路径均有测试；产品路径可在禁止读取旧全局计划/工具模式的测试下工作，未增加启动时配置/存储 IO。
- S3-A6 对应全部：相关/完整测试、lint、格式、严格文档、构建、Python 兼容及既有启动门禁通过，父任务 A1—A6 重新集成验收。
