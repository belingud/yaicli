# 第一阶段：统一命令定义与拆分工具入口

## Goal

完成父任务 R1：统一命令定义，明确工具声明、权限评估、执行及展示的边界，降低新增命令和维护工具调用时的重复修改成本。用户可见行为保持 v0.26.0 基线不变。

## Background

证据来源：[父任务研究笔记](../11-27-core-organization-refactor/research/organization-review.md)。关键位置：cmd_handler.py:71、95、171、1333；tools/__init__.py:339、501、560、689；llms/client.py:868。

帮助和补全已经共享 COMMAND_INFO，不重建一套新系统。本阶段沿用全局默认运行时和当前会话所有权，明确接缝；会话状态隔离属于第三阶段。

## Requirements

- S1-R1：处理函数、别名、帮助、补全与参数接收规则共用一份定义。保留每条命令现有语法、命令 token 大小写处理、原始参数内容、未知输入及 !/！入口语义。
- S1-R2：工具声明、过滤、缓存与执行分离；OpenAI、Anthropic、Gemini 和 MCP 继续看到现有工具集合与 schema。
- S1-R3：工具调用的权限评估独立于 provider 请求循环。确认、会话/持久授权、审计、配对消息及继续请求按原有顺序衔接。
- S1-R4：执行和展示分工明确；文件保护、备份、撤销、检查点、输出截断、完整参数记录及用户工具覆盖保持原语义。
- S1-R5：现有 yaicli.tools 公共函数和 CmdHandler 入口可用；不引入新的功能配置、运行时依赖或扩展框架。

## Feature examples

沿用父 PRD E1—E3，另外冻结：

~~~text
> /rewind abc
Usage: /rewind [id]
~~~

在满足现有前置条件的会话中，非法参数仍输出既有错误，不执行回退。/modelx hello 仍是普通提示词，不能被 /model 或 /mode 的前缀匹配吞掉；/fork 1 My Review Chat 中的标题必须保持原样。帮助和补全展示、stderr 路径、确认次数及退出行为均不变；? 别名保持可执行且不进入斜杠补全列表。

## Out of scope

不调整 CLI 会话职责、计划数据格式、全局状态所有权、provider 实现或工具执行签名。不修复既有 MCP 名称原地去前缀的行为；不合并无关格式调整。

## Acceptance criteria

- S1-A1 对应 S1-R1：覆盖全部命令和别名的注册、帮助、补全一致性；参数命令与无参数命令分别保留原分派规则，未知/近似名称和标题大小写回归通过。
- S1-A2 对应 S1-R2：三种 provider 声明、选择模式、计划/执行模式与缓存失效行为等价；MCP 懒加载及用户同名覆盖回归通过。
- S1-A3 对应 S1-R3：standard/readonly/trusted、危险 shell、确认关闭、非交互、规则授权、拒绝及持久失败路径保持决策、确认、审计和消息 ID 一致。
- S1-A4 对应 S1-R4：真实临时文件的创建/编辑/撤销/回退测试通过，流式确认和 Ctrl+O 详情保持；截断只执行一次，ok 标志不误解为业务成功。
- S1-A5 对应 S1-R5：明确的工具模块边界、薄兼容入口和现有注入方式通过检查；相关与完整测试、lint、格式和启动门禁通过，记录可回退 PR。
