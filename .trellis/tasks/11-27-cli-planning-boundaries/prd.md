# 第二阶段：拆分 CLI 协调职责与计划模块

## Goal

完成父任务 R2：将 CLI 中的会话操作、机器输出和计划协调分离，归拢计划实现，使这些行为可以通过明确依赖分别测试，减少命令层对 CLI 私有状态的访问。

## Background

依赖第一阶段 11-27-command-tool-boundaries 合并到 master。基线证据：cli.py:162、676、873、1328、1724、2046、2313；cmd_handler.py:551、849、866、1130；plan_mode.py:1、526；plan_store.py。见父任务研究笔记。

第一阶段的工具及命令入口为本阶段提供接缝；本阶段不同时改变会话配置及计划状态的所有权，该项由第三阶段负责。

## Requirements

- S2-R1：CLI 主要承担应用组装、模式分派、REPL 和生成期间的终端生命周期；会话保存/加载/恢复及检查点协调由明确的会话服务承担。
- S2-R2：机器输出的结果构造、事件输出、用量/错误和退出状态映射可独立验证；stdout/stderr、JSON/NDJSON、事件顺序和原有 CLI 公共状态契约不变。
- S2-R3：计划模型、校验、存储、状态服务、提示词、编辑器和应用协调有明确边界，计划包不导入 CLI/entry，叶子层不依赖 Rich/终端交互。
- S2-R4：会话、计划、模型/角色切换、重试和检查点命令通过命名服务入口操作状态；迁移后的命令不读写对应 CLI 私有字段或调用其私有业务方法。
- S2-R5：保留历史数据、注入点及兼容导入路径，生成线程、确认、取消、Ctrl+O 与检查点锁顺序不变。

## Feature examples

沿用父 PRD E1—E3。以下行为由现有测试冻结：

~~~text
> /rewind
Save this chat with /save before using checkpoints.
~~~

临时会话仍在现有 stderr 路径拒绝回退，不修改工作区。持久会话的 /fork [id] [title] 仍先保存当前对话，再回到目标检查点，使用同一工作区，不创建 Git 分支。ai -p --json 仍只输出原有 JSON 对象，普通请求不附加计划字段；stream-json 的结束事件和退出码保持一致。

## Out of scope

不新增会话/计划行为，不改变 PlanSession 所有权、不删除全局配置，不重写检查点恢复算法、存储协议、provider 或终端库。旧缺陷另行记录。

## Acceptance criteria

- S2-A1 对应 S2-R1/R4：会话操作和计划协调的构造参数不包含整个 CLI；相关命令可用最小真实依赖进行行为测试，不需要模拟几十个 CLI 属性。
- S2-A2 对应 S2-R2：相同确定性输入的 stdout/stderr、JSON 字段/值、NDJSON 顺序和退出码与第一阶段基线相同，真实用量与 finish_reason 保留。
- S2-A3 对应 S2-R3：产品内部使用计划包；plan_mode/plan_store 仅保留必要兼容入口，无重复模型/缓存；模型/校验/存储无 CLI/终端反向依赖。
- S2-A4 对应 S2-R4/R5：源码和行为测试共同确认命令不再直接写 _client/_last_turn_snapshot 或调用会话/计划/检查点私有业务方法；公共 CLI 契约继续委托有效状态。
- S2-A5 对应 S2-R5：旧聊天和计划可恢复，检查点跨进程回退实际字节一致；流式取消和遗留工作线程不污染下一轮；完整质量及启动门禁通过。
